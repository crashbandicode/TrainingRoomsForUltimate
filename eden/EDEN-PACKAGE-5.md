## U4 investigation (2026-11-02, static; owned ELF 13.0.5 + the carried `mii_hud_portrait.rs`, origin ours-new)
- Prior art (ours-new `src/runtime/mii/mii_hud_portrait.rs`, read on `stream/pkg6b`): the Mii portrait does **not** create a texture from file bytes. The game's own portrait renderer renders into a request whose storage holds a registered GPU *descriptor* (`req + 0x180`); the carried code then binds that descriptor to a pane with the game function `main+0x379e9c0(pane, descriptor, index)`.
- Decoded `379e9c0` (disassembly of the owned ELF): `material = fn_597e0(pane)`; if `index < (material+0x14 & 3)` then `texmap = [material + 0x18] + index * 16` and `[texmap + 8] = descriptor`; the previous value is saved at `pane + 0x100 + index * 16` with a flag byte at `pane + 0x108 + index * 16` (restored on the next call for that index; index 0 also drops a cached reference at `pane + 0x130/0x138` and clears `pane + 0x235`). So the **bind half of U4 is known**: a picture pane's TexMap entry takes a descriptor pointer at `+8`, and the game function does it with its own undo bookkeeping.
- Not known (and not in the prior art): how to **make** a descriptor from a BNTX file's bytes: the GPU texture and texture view, a slot in the game's texture descriptor pool, and the descriptor object `379e9c0` expects. The Mii path gets it from a render request. The game's own stage select makes them through the ui2d resource accessor's texture registration; those functions are not identified yet in the owned ELF (no symbols; the Ghidra project `research/game-13.0.5/ghidra-proj` exists; REA was not opened on the 87 MB ELF in this session).
- Next (root route): (1) find the ui2d texture-registration callback (the game registers each layout texture's view with the descriptor pool when a layout archive's BNTX is loaded: it runs once per layout load, so a breadcrumb exists at the archive hook's callers); (2) call it, or its pieces, with a BNTX the plugin read through `arcrop_load_file`, for one test texture; (3) bind with `379e9c0`. Item icons need none of this (built into the recipe as the plugin's own assets).
