## R2-1 design in one picture

```
row guards (4 tables) --> usable(row) --+--> Granted (offsets)  --> game::natives::at / state_natives::at   (no call without a grant)
                                        |
                                        +--> blocked_by(unit) = own rows + Training + CPU core (CPU units) + CROSS_NEEDS[unit]
                                                  |                         ^ generated by tests/capabilities.rs from src/runtime
                                                  v
                                   boot installs the unit only when nothing blocks it; the install line says
                                   `<feature>=not_installed reason=site:<row>`
```

Boundaries (functions the call graph stops at; each reads its install flag first, `every_boundary_checks_its_gate_first`):
`states::frame` (ACTIVE), `cpu::{frame_advantage, mash_facts, mash_player_position, apply_mash}` (MASH_ON), `cpu::ledge_facts`
(LEDGE_ON), `cpu::{tech_facts, apply_tech}` (TECH_ON), `cpu::apply_defence` (DEFENCE_ON), `recorder::{request_playback,
on_state_restored, on_p1_poll}` (ENABLED). New flags: `cpu::set_ledge_on`, `cpu::set_defence_on`, `recorder::set_enabled`.

Regenerate the table after a runtime change:
`cargo test --test capabilities print_cross_needs -- --ignored --nocapture` and paste into `src/model/capabilities.rs`
(`cross_needs_match_the_call_graph` fails otherwise). `explain` (ENTRY=<module::fn> ROW=<row>) prints why an entry reaches a row.

## Known limits (reported to the lead)

- The scanner over-approximates (a method call reaches every function of that name; a bare name reaches its own file or an imported
  one) and cannot see calls through data (function-pointer tables: the one, `ui::hud::run -> hud_draw::draw`, is declared in the test).
  A new indirect call must be declared there.
- Import (lead ruling 2026-11-02): every I/O error, discovery or copy, withholds `migration.json` (retry next boot); only the by-design skips
  (staging folders, exists, too_large) allow it. SPEC-core-08 rules 4, 4a and 5 say so (docs-only commit on `review/menu-proposal`: `ad9c15f`).
- The input display's reads in the input-delay hook (`status_kind`, `fighter_manager_get_entry`) are behind `input_display::on_p1_poll`'s own flag
  (`Feature::InputDisplay`, a unit with no rows of its own), so Input Delay installs on its own rows and the display degrades apart. The CPU core
  keeps the reset hub's `fighter_information` and `is_operation_cpu` in its closure (its role test is the core's own).
