# Native tech timing (13.0.5)

The timing reader uses the Fighter ControlModule address point `main+0x4f85de0`, installed by the constructor at `0x6b8530`. The base class address point rejects fighter objects. The constructor stores `this+0x20` at `this+0x110`. Exact vtable byte offsets `0x178/0x220/0x228/0x230/0x250` resolve to stick, trigger word, current count, previous count and native trigger check respectively. All call targets retain exact 64-byte guards.

The update at `0x3f9140` produces the native positive-edge word. Its loop at `0x3f9530` copies the old current count into previous and resets current to zero on that edge; otherwise current increments and saturates at 254. Therefore a press at contact has age zero. Previous is the pre-update age, one less than the elapsed gap between presses; comparisons use the unchanged native value. No physical shoulder sample or counter decrease establishes a press.

The common check at `0xed460` accepts `count < base * multiplier` and `lockout <= previous`. Multiplication and mixed comparison use f32, without truncating the window. Window, lockout and reaction are read live. DamageFall and held-input paths remain distinct. Runtime ordering and availability require exact-build trace validation; static counter origin alone is not a host-input timing measurement.

Actual entered native contact statuses are independently proven through the common constant table and status requests: floor DOWN 80 / bounce 78; wall STOP_WALL 108 / bounce 76; ceiling STOP_CEIL 109 / bounce 77. STOP statuses also occur outside tech attempts: grading still requires the owned attempt, valid first contact and actual entered status. Unknown status or unreadable contact remains unavailable.
