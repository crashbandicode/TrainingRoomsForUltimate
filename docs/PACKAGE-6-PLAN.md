## 2. How files are carried (so a re-sync is a copy)

A carried file is **never hand-edited**. `tools/carry_pkg6.py` (written in S6-1) reads a manifest
(`docs/provenance/pkg6-carry-manifest.json`: stage path, destination path, transform set, source sha256, destination
sha256) and for each entry:

1. checks the stage file's sha256 against the manifest (or, with `--stage <name> --update`, takes the new file and
   lists it for the CARRY-OVER ledger);
2. copies it with a deterministic **path rewrite table** (generated from the manifest itself): `crate::x` inside the root
   crate, `training_mod_consts::x` / `crate::x` inside the consts crate, `training_mod_mii::x` /
   `training_mod_consts::mii::x`, `training_mod_tui::x`, `training_mod_sync::{read,assign,lock_write}` (to the
   `parking_lot` shim) become `crate::model::<area>::x` / `crate::runtime::<area>::x`; `#[path]` includes in by-path
   tests are rewritten the same way;
3. applies, if any, a patch file `docs/provenance/pkg6-patches/<name>.patch` (a clean-room edit that no rewrite can
   express; each is a ledger row, one reason each);
4. writes the destination and its sha256; `tools/carry_pkg6.py --verify` (also a host test) fails if a carried file was
   edited by hand.

Things the carried files expect from the fork's mixed files are provided by **adapter modules** in `src/model/compat/`
and `src/runtime/compat/` (the names the carried code uses are kept: `logging::diagnostic`, `common::…`, the typed menu
view). Adapters are our new code and stay small. So F1/F2 (W19's patched stage) and F3 (W20) land as
`carry_pkg6.py --stage <patched> --update`: new sha256 in the manifest, a re-run of the tests, a ledger line.

**Module layout (decision D2, recommended).** One crate, as the playbook says (`cdylib` only; no `rlib` workspace
members): pure carried code under `src/model/<area>/` (areas `swap`, `mii`, `preload`, `kirby`, `items`, `stages`,
`lobby`, `seams`, `p1`, `compat`), Switch-only carried code under `src/runtime/<area>/`, one `#[path]` mod line each in
`src/model.rs` / `src/runtime.rs` (package 1's by-path convention), hook sites in `src/model/sites_swap.rs`-style
files registered with one line. Fork tests that are crate integration tests are rewritten (by the same table) into by-path
includes of only the subtree they need, so each test binary does not recompile all of `model`. Alternative: keep
`training_mod_mii` as a path crate (zero edits, but a workspace member and an `rlib`).
