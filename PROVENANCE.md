## Method

`provenance_scan.py` lists the stage's files (`rg --files`, so `.gitignore`d
build output is excluded), looks each path up in the merge-base tree and
classifies it:

- **ours-new**: the path does not exist upstream;
- **upstream-identical**: byte-identical;
- **mixed**: both exist and the text differs; the script records how many
  upstream lines the stage retains, how many stage lines upstream does not
  have ("fork-only"), and the fork-only line ranges (stage line numbers);
- **binary-differs**: both exist, binary, different;
- upstream files absent from the stage are **dropped by fork**.

A new file whose basename matches an upstream file with a similarity ratio of
0.3 or more is flagged as a possible move (three `Cargo.toml` files were; all
are new crates, not moves). `feature_groups.py` then assigns every file to a
feature by path rules (first match wins) and sums the line counts.

## Standalone validation lockfiles
The Cargo.lock files beside the vendored/local library manifests are project-generated validation metadata, not upstream source edits. Before the RC freeze, offline resolution pinned every package/version/source/checksum to an identity already present in the shipped root Cargo.lock (including serde_json1.0.151). They let standalone --locked tests run without mutating the frozen source. SDK Rust source and manifests remain unchanged.
